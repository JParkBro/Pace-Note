# 광고 전략

## 1. v1 결정

**v1에는 광고 · 인앱 결제가 없습니다.** 서버 비용이 0원(Spark, 결제 수단 없음)이라 수익 없이도 유지할 수 있고, 첫 출시는 "기록이 끊기지 않는 앱"이라는 신뢰를 쌓는 데 집중합니다. 그래서 v1 모듈에는 `core:ads` · `core:billing`이 없습니다.

광고를 넣기로 하면 이 문서를 먼저 고치고, `roadmap.md` 4장 절차(기능 정의 → 영향 점검 → 플래그)로 진행합니다.

## 2. 광고를 넣게 될 때의 원칙

데이즈에서 정한 원칙을 그대로 따르고, 러닝앱 특유의 금지 영역을 더합니다.

| 원칙 | 내용 |
|---|---|
| 배너 없음 | 앱이 예뻐 보이지 않게 만드는 배너 광고는 쓰지 않음 |
| **러닝 중 금지** | P1 ~ P5, 진행 중 알림, 음성 안내 어디에도 광고 없음. 카운트다운 전후도 금지 |
| 보상형 중심 | 사용자가 원해서 보는 광고만 주력 |
| 전면광고는 보조 | 작업 완료 후 화면 전환 시점, 하루 1~2회, 설치 후 3일 미노출 |
| 핵심 기능은 무료 | 기록 · 결과 · 기록 목록 · 기본 통계 · 기본 공유 카드 · 백업은 광고와 무관하게 항상 사용 가능 |

## 3. 후보 위치 (검토용)

| 종류 | 후보 | 판단 |
|---|---|---|
| 전면광고 | P6 결과 → "완료"로 홈에 돌아갈 때 | 가장 자연스러운 전환 시점. 빈도 제한 필수 |
| 보상형 | 공유 카드 추가 템플릿 · 배경 해금 | 공유 카드에 앱 이름이 들어가 홍보 효과도 있음 |
| 보상형 | 테마 해금 (기본 1종 + 광고로 나머지) | 테마가 4종뿐이라 효과 작음. 테마를 늘릴 때 검토 |
| 보상형 | 고급 통계 (월간 리포트 · 페이스 추세) | v2 통계 기능과 함께 검토 |
| 광고 제거 1회 구매 | 전면광고를 넣는 경우에만 의미 | 전면광고가 없으면 불필요 |

## 4. AdMob 정책 체크리스트 (도입 시)

- [ ] 앱 시작 · 종료 시 전면광고 금지
- [ ] 사용자 행동 2회당 최대 1회 수준의 빈도
- [ ] 보상형 광고는 보상 내용을 미리 명확히 안내
- [ ] 맞춤 광고 동의(UMP), 대상 연령 설정
- [ ] app-ads.txt를 개발자 웹사이트(Hosting) 루트에 배포
- [ ] Play Console 앱 콘텐츠 "광고 포함", 데이터 보안(광고 ID) 갱신

## 5. 구현 메모 (도입 시)

- 데이즈의 `core:ads`(`RewardedAds` · `rememberRewardedAdLauncher`, Root가 Event로 띄우고 결과를 Action으로) 구조를 그대로 가져옵니다.
- 서버 측 보상 확인(SSV)은 Cloud Functions가 필요해 Spark에서는 쓸 수 없습니다. 보상이 서버 자원(저장 한도 등)과 무관한 것(템플릿 · 테마 해금)만 기기 쪽 확인으로 처리합니다.
- 광고 빈도 · 첫 노출 일수는 Remote Config로 조절합니다.
